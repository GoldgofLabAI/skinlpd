# Methods

## Overview

We developed a computational pipeline for quantifying cell density in high-attention regions of whole-slide images (WSIs) using vision transformer (ViT) attention maps and spatial cell detection data. The pipeline integrates tissue segmentation, attention-weighted patch identification, and cell density metrics to enable quantitative analysis of spatial biology patterns.

## Cell Detection and Segmentation

### CellViT Inference

Whole-slide images were processed using CellViT++ (CellViT-Inference v1.0.0b) for automated cell detection and classification. CellViT is a vision transformer-based model that performs nuclear segmentation and phenotyping on histopathology images.

**Model Configuration**:
- **Model**: CellViT-SAM-H-Backbone (ViT-H), which uses the SAM (Segment Anything Model) backbone
- **Output Formats**: 
  - GeoJSON format for tissue segmentation contours
  - Cell graph representation (`.pt` format)
  - Snappy compression applied to output files

**Processing Command**:
```bash
cellvit-inference \
    --model SAM \
    --geojson \
    --graph \
    --compression \
    --outdir "$OUTDIR" \
    process_dataset \
    --wsi_filelist "$FILELIST"
```

**Dataset Processing**:
- Slides were processed in batch mode using a CSV filelist produced by `build_cellvit_filelist.py`
- The CSV filelist format follows the CellViT specification, containing at minimum a `path` column with WSI file paths
- Optional `wsi_mpp` and `wsi_magnification` columns can be provided for metadata handover if not available in WSI headers

**Environment**:
Processing used CellViT-Inference v1.0.0b. Install that package in a dedicated environment; this repository does not vendor the weights.

**Output Structure**:
For each processed WSI, CellViT generates:
- `cell_detection.json.snappy`: Snappy-compressed JSON file containing:
  - Cell centroids in level-0 pixel coordinates
  - Cell type classifications (mapped via `type_map`)
  - WSI metadata including `base_mpp` (microns per pixel)
- Tissue segmentation contours (if GeoJSON output enabled)
- Cell graph representation (if graph output enabled)

The cell detection results serve as the primary input for subsequent density analysis, providing spatial coordinates and type annotations for all detected nuclei. For detailed documentation on CellViT processing options, see the [CellViT Inference documentation](https://tio-ikim.github.io/CellViT-Inference/examples.html#csv-filelist-processing).

## Data Preprocessing

### Input Data Sources

The analysis pipeline requires three primary data sources for each WSI:

1. **Tissue Segmentation (GeoJSON)**: Whole-slide tissue segmentation contours stored in GeoJSON format, containing polygon features defining tissue boundaries.

2. **Attention Maps (HDF5)**: Vision transformer attention scores for each patch, stored in HDF5 format with the following structure:
   - `attention`: Raw attention values (shape: `[n_patches]`)
   - `coords`: Patch coordinates in level-0 pixel space (shape: `[n_patches, 2]`)
   - `patch_size_level0`: Patch size in pixels at level-0 resolution

3. **Cell Detection Data (Snappy-compressed JSON)**: Spatial cell detection results generated by CellViT, containing:
   - Cell centroids in level-0 pixel coordinates
   - Cell type annotations (mapped via `type_map`)
   - WSI metadata including `base_mpp` (microns per pixel) for spatial calibration
   - File format: `cell_detection.json.snappy` located in `output/{base_filename}/`

### Coordinate System Alignment

All spatial data (segmentation, attention patches, and cell centroids) are aligned to level-0 pixel coordinates. The `base_mpp` value from cell detection metadata is used to convert pixel-based measurements to physical units (mm²) for density calculations.

## Attention-Based Patch Identification

### High-Attention Patch Selection

Patches with attention scores above a user-defined percentile threshold (default: 80th percentile) are identified as high-attention regions:

\[
T_\alpha = \{i : a_i > \text{percentile}(a, \alpha)\}
\]

where \(a_i\) is the attention score for patch \(i\), and \(\alpha\) is the percentile threshold (e.g., 80%).

### Patch Coordinate Extraction

For each patch, the top-left corner coordinates are extracted from the `coords` array, and the patch extent is defined as a square region of size `patch_size_level0 × patch_size_level0` pixels.

## Tissue Segmentation and Rasterization

### Segmentation Polygon Construction

Tissue segmentation polygons are extracted from GeoJSON features and combined into a single union polygon using Shapely's `unary_union` operation. This creates a unified representation of all tissue regions in the WSI.

### Rasterization for Efficient Area Calculation

To enable fast tissue area calculations for thousands of patches, we employ a rasterization approach:

1. **Resolution Selection**: The segmentation polygon is rasterized at a resolution of 1 pixel per patch size, providing patch-level accuracy while maintaining computational efficiency.

2. **Memory Optimization**: For large WSIs, raster dimensions are capped at 5000×5000 pixels (~25 MB memory) to prevent excessive memory usage. When capping is applied, the pixel size is recalculated to maintain full coverage.

3. **Rasterization Implementation**: 
   - Primary method: Uses `rasterio.features.rasterize()` for efficient polygon-to-raster conversion
   - Fallback method: Grid-based sampling with Shapely's `contains()` method when rasterio is unavailable

4. **Coordinate Transformation**: A transform matrix maps between world coordinates (level-0 pixels) and raster indices, accounting for rasterio's top-left origin coordinate system.

### Tissue Area Calculation per Patch

For each patch, tissue area is calculated by:

1. **Coordinate Transformation**: Convert patch corners from world coordinates to raster indices
2. **Raster Sampling**: Extract the corresponding region from the rasterized mask
3. **Coverage Ratio**: Calculate the proportion of tissue pixels within the patch region
4. **Area Conversion**: Convert to physical units:
   \[
   A_i = \text{patch\_size}^2 \times \text{coverage\_ratio} \times \left(\frac{\text{base\_mpp}}{1000}\right)^2 \quad [\text{mm}^2]
   \]

## Cell Density Metrics

We compute two complementary cell density metrics that leverage attention scores differently:

### Method 1: Thresholded (High-Attention) Cell Density

This method computes cell density using only patches above the attention threshold:

\[
D_{\text{high-attn}}(\alpha) = \frac{\sum_{i \in T_\alpha} C_i}{\sum_{i \in T_\alpha} A_i} \quad [\text{cells/mm}^2]
\]

where:
- \(T_\alpha\): Set of patches with attention > α-th percentile
- \(C_i\): Number of cell centroids within patch \(i\)
- \(A_i\): Tissue area of patch \(i\) (in mm²)

**Implementation Details**:
- Cell counting uses vectorized NumPy broadcasting to efficiently determine which cells fall within each patch
- Only patches that overlap with the segmentation bounds are included in the calculation
- Patches completely outside tissue regions are excluded (tissue area = 0)

### Method 2: Attention-Weighted Cell Density

This method uses all patches, weighted by their attention scores:

\[
D_{\text{weighted}} = \frac{\sum_{i \in T} a_i \cdot C_i}{\sum_{i \in T} a_i \cdot A_i} \quad [\text{cells/mm}^2]
\]

where:
- \(T\): Set of all patches
- \(a_i\): Attention score for patch \(i\)
- \(C_i\): Number of cell centroids within patch \(i\)
- \(A_i\): Tissue area of patch \(i\) (in mm²)

**Implementation Details**:
- All patches are included, with attention scores serving as weights
- Patches with zero tissue area contribute zero to both numerator and denominator
- This method provides a continuous weighting scheme rather than a binary threshold

### Cell Counting Optimization

Cell counting is performed using vectorized NumPy operations:

1. **Broadcasting**: Create boolean masks for all patch-cell pairs simultaneously using NumPy broadcasting
2. **Vectorized Summation**: Count cells per patch using `np.sum()` along the appropriate axis
3. **Efficiency**: This approach scales as O(n_patches × n_cells) but is highly optimized through vectorization

### Optional Cell Filtering

An optional preprocessing step filters cells to only those within the segmentation polygon:

- **Purpose**: Accounts for potential discrepancies between tissue segmentation used for cell detection versus the segmentation used in this analysis
- **Implementation**: Uses Shapely's `prepared` geometries for efficient point-in-polygon checks
- **Trade-off**: More accurate but computationally expensive; typically not necessary for most analyses

## Postprocessing and Visualization

### Visualization Components

The pipeline generates comprehensive visualizations that overlay multiple data layers:

1. **Segmentation Outline**: Tissue boundaries from GeoJSON, plotted as blue polygons with semi-transparent fill

2. **High-Attention Patches**: Patches above the attention threshold, displayed as semi-transparent red rectangles (α = 0.3)

3. **Tissue Coverage Ratches**: Optional display of tissue coverage ratio (0-1) as text annotations at the center of each high-attention patch

4. **Cell Centroids**: Optional display of sampled cell centroids (default: 100% sampling) that fall within high-attention zones, plotted as green scatter points

5. **Windowing**: Optional viewport restriction to a specified rectangular region for focused analysis

### Cell Type Filtering

Cells can be filtered by type using a comma-separated list of cell type names (case-insensitive). The filtering uses the `type_map` from cell detection metadata to match cell type IDs to names.

### Output Generation

- **Visualization PNGs**: High-resolution plots saved with descriptive filenames including the base filename and attention threshold
- **Results CSV**: Batch processing generates a CSV file with columns:
  - `base_file_name`: Case identifier
  - `density_high_attn`: Thresholded density metric (cells/mm²)
  - `density_weighted`: Attention-weighted density metric (cells/mm²)
  - `status`: Processing status (success/failure)
  - `processing_time`: Computation time in seconds
- **Processing Logs**: Detailed logs saved to `processing.log` in the output directory, capturing computation times, coordinate ranges, and diagnostic information

## Batch Processing

### Case Discovery

The pipeline supports batch processing of multiple WSIs:

1. **CSV-Based Discovery**: Reads a CSV file with a `base_file_name` column to determine which cases to process
2. **Directory-Based Discovery**: Automatically discovers all available cases by scanning the cell detection directory

### Incremental Results Tracking

Results are written incrementally to the CSV file as each case is processed, enabling:
- Progress monitoring during long batch runs
- Recovery from interruptions (completed cases are not reprocessed)
- Real-time result inspection

### Error Handling

Cases with missing required files are automatically skipped with appropriate logging. The pipeline continues processing remaining cases even if individual cases fail.

## Computational Optimizations

### Rasterization Benefits

The rasterization approach provides significant performance improvements over direct polygon intersection:

- **Speed**: O(n_pixels) one-time rasterization cost vs. O(n_patches × polygon_complexity) for repeated intersections
- **Scalability**: Handles tens of thousands of patches efficiently
- **Memory**: Controlled memory footprint through intelligent downsampling and dimension capping

### Vectorized Operations

Key computational steps use NumPy vectorization:

- Cell counting: Broadcasting operations for O(n_patches × n_cells) complexity with optimized C-level execution
- Attention-weighted sums: Element-wise multiplication and summation using optimized NumPy operations

## Software Implementation

The pipeline is implemented in Python 3, utilizing the following key libraries:

- **Shapely**: Geometric operations and polygon manipulation
- **Rasterio**: Efficient polygon rasterization (with Shapely fallback)
- **NumPy**: Vectorized numerical computations
- **H5py**: HDF5 file I/O for attention maps
- **Snappy**: Decompression of cell detection JSON files
- **Matplotlib**: Visualization generation
- **Pandas**: CSV result management

The codebase is modularized into reusable functions for each processing stage, enabling easy integration into larger analysis workflows and facilitating maintenance and extension.

## Density formulas

```
Thresholded (High-Attention) Cell Density
---------------------------------------

Let:
- i ∈ T_α : tiles with attention score above the α-th percentile (e.g., α = 80)
- C_i : number of cells (nuclei) in tile i
- A_i : tissue area of tile i (in mm^2)

LaTeX formula:

D_{high-attn}(α)
=
\frac{
    \sum_{i \in T_{α}} C_i
}{
    \sum_{i \in T_{α}} A_i
}
\quad [cells/mm^2]


------------------------------------------------------------

Attention-Weighted Cell Density (No Threshold)
---------------------------------------------

Let:
- a_i : attention score for tile i
- C_i : number of cells (nuclei) in tile i
- A_i : tissue area of tile i (in mm^2)

LaTeX formula (recommended implementation):

D_{weighted}
=
\frac{
    \sum_{i \in T} a_i \, C_i
}{
    \sum_{i \in T} a_i \, A_i
}
\quad [cells/mm^2]
```
